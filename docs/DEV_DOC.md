## 1. 产品定义

**一句话**：你的 AI 在干活、等你确认、干完了、出错了——桌宠第一时间替它告诉你；人离开电脑，手机也能收到。

- 定位：面向 AI 编程/AI 助手重度用户（Claude Code、Codex、Cursor、Muse 等 CLI/Agent 工具用户）的桌面状态伴侣。
- 核心价值：解决「发起长任务后不敢走开、回来才发现它早就在等确认」的真实痛点；顺带提供情绪价值（桌宠陪伴）与轻量用量感知。
- 不是：聊天客户端（MVP 不做对话）、用量计费套件（只做轻量统计，二期）、自动化控制工具（只报状态，不代替用户点确认）。

## 2. 总体架构（三层，层间只走协议）

```
[适配器层]                [状态中枢 Hub]              [表现层]
Claude Code hooks 脚本 ─┐
Codex hooks/notify 脚本 ─┼─→ 本地事件接口 ─→ 状态归一 ─→ 桌宠窗口（Electron）
Cursor hooks 脚本 ──────┤   (127.0.0.1)    去抖/聚合    控制页（设置/状态面板）
通用 Webhook / CLI ─────┘                    │
                                             └→ 通知器（系统通知 / 外发 Webhook）
```

- **适配器层**：每个 AI 工具一份零依赖小脚本（Node 单文件），由各工具的官方 hook 机制调用，把原生事件翻译成第 3 节的统一事件，POST 到 Hub。脚本必须快进快出（<200ms），失败静默（绝不能阻塞或搞挂宿主 AI 工具）。
- **状态中枢 Hub**：跑在桌宠 App 的主进程内（MVP 不做独立守护进程）。负责鉴权、归一、去抖、多会话聚合、陈旧检测，并把当前状态广播给表现层与通知器。
- **表现层**：透明置顶桌宠窗口 + 控制页窗口。只消费 Hub 的聚合状态，不直接读任何 AI 工具的文件。

## 3. 统一状态协议（本产品的核心资产，版本化管理）

### 3.1 状态枚举（五态 + 离线）

| 状态 | 含义 |
|---|---|
| `idle` | 已连接，无任务（休息中） |
| `working` | 正在执行任务 |
| `waiting` | 停下来等用户确认/输入（最高优先级） |
| `done` | 刚完成一轮（瞬时态，展示 8 秒后回落 idle） |
| `error` | 出错终止 |
| `offline` | 该来源进程/会话已结束或超时无心跳 |

### 3.2 事件格式（v1）

```json
{
  "v": 1,
  "source": "claude-code | codex | cursor | generic",
  "session": "<会话唯一 id>",
  "state": "working",
  "ts": 1762588800000,
  "project": "<项目目录名，可选，只允许 basename>",
  "title": "<可选短文本，≤40 字，只允许任务标题类信息>",
  "beat": true
}
```

- 接口：`POST http://127.0.0.1:<port>/v1/event`，请求头 `x-petlink-token: <本机令牌>`。端口默认 17321，被占用时顺延并写入状态文件 `~/<appdata>/petlink/hub.json` 供适配器发现；令牌首次启动生成，存本机应用数据目录，权限 600。
- 适配器找不到 Hub 时：静默退出（可选写一行本地日志），不得报错弹窗。
- `beat: true` 表示心跳（状态不变、仅续命），Hub 只刷新时间戳不触发表现变化。

### 3.3 聚合与优先级规则

- Hub 按 (source, session) 维护会话表；桌宠展示的是**全局聚合态**：
  优先级 `waiting > error > done > working > idle`；`offline` 会话不参与聚合。
- 多个会话同为 working 时，展示 working，控制页列出全部会话明细。
- **陈旧检测**：working 会话超过 90 秒无任何事件 → 标记「安静」（仍 working，表现层降亮度）；超过 10 分钟 → 该会话降为 idle 并在控制页标注「疑似结束」。waiting 不超时降级（它本来就在等人）。
- **去抖**：同一会话 300ms 内的重复事件合并；done 展示窗口内新 working 事件立即接管。

### 3.4 隐私约束（写进协议，不靠自觉）

- 事件里**禁止**携带：代码内容、完整提示词、文件完整路径（只允许项目目录 basename）、密钥类字段。适配器在发送前对 title 做长度截断与敏感词过滤（token/key/password/密钥）。
- Hub 只监听 127.0.0.1；状态数据只存内存 + 本地最近 100 条事件环形日志（供控制页诊断，可一键清空）。
- MVP **无任何遥测**，不联网（外发 Webhook 为用户显式配置项，默认关）。

## 4. 适配器规格

每个适配器由「脚本 + 配置管理器条目」组成。脚本语言统一 Node（各工具环境都保证能跑 node 或自带运行时；若目标机无 node，用各工具自带运行时兜底方案在脚本头注释说明）。

### 4.1 Claude Code 适配器（一期，最高保真）

官方 Hooks 事件映射（依据 Claude Code 官方 hooks 文档，2026-11 核对）：

| Hook 事件 | 映射 |
|---|---|
| SessionStart | idle（会话登记） |
| UserPromptSubmit | working |
| PreToolUse / PostToolUse | working + beat |
| Notification / PermissionRequest | waiting |
| Stop | done |
| StopFailure | error |
| SessionEnd | offline |

- 安装位置：`~/.claude/settings.json` 的 `hooks` 字段，命令指向 App 随附的适配器脚本绝对路径。
- 会话 id 用 hook 输入的 `session_id`；project 用 `cwd` 的 basename。

### 4.2 Codex 适配器（一期）

两条通道，任一可用即达标，都有更好：

1. **hooks 通道**：Codex 现行 hooks 体系（`~/.codex/hooks.json` 或 config.toml 的 `[hooks]` 表，二选一，不要混写——混写 Codex 会警告）。事件尽量对齐 4.1 的映射粒度。
2. **notify 通道（保底）**：`~/.codex/config.toml` 顶层 `notify = ["<node>", "<适配器脚本>", "--codex-notify"]`。该通道目前只发 `agent-turn-complete` 一种事件（官方配置文档明示），只映射 done。**注意 notify 只认用户级 config.toml，项目级不生效。**
3. working 心跳增强（可选开关，默认关）：tail 本机会话日志 `~/.codex/sessions/` 的新事件做 beat。涉及读日志，必须在控制页显式开启并注明。

### 4.3 Cursor 适配器（二期）

依据 Cursor 官方 hooks 文档：`~/.cursor/hooks.json`，事件映射：

| Hook 事件 | 映射 |
|---|---|
| sessionStart | idle |
| beforeSubmitPrompt | working |
| preToolUse / postToolUse / postToolUseFailure | working + beat（失败置 error 闪烁一次后回 working，以 Hub 规则为准） |
| afterAgentResponse | beat（不直接置 done） |
| stop（status 字段） | completed→done / aborted→idle / error→error |
| sessionEnd | offline |

### 4.4 通用接入（一期就要，成本最低、生态价值最高）

- 任意工具/脚本：`curl -X POST 127.0.0.1:<port>/v1/event -H "x-petlink-token: <令牌>" -d '{...}'`。
- 随附 CLI：`petlink send --source generic --state done --title "构建完成"`，供 CI、脚本、其他 AI（含 Muse）调用。
- Muse 专用适配器：截至 2026-11 无公开的本地状态接口，**先只走通用接入**，协议层预留 `source: "muse"`；后续官方开放再补。

## 5. 桌宠表现层规格

- 窗口：无边框、透明、置顶、可拖拽移动，位置记忆；右键菜单（控制页 / 大小 / 置顶开关 / 退出）；左键点击 = 摸摸互动（表情反馈，不打断状态展示）。
- **大小可调**：控制页滑杆 50%–200%，实时生效并记忆（此条为负责人明确要求）。
- 动画系统：帧序列（WebP 优先，PNG 兼容）+ 播放器（fps 可配、循环/单次）。状态→动作映射（内置第一只角色）：

| 状态 | 动作 | 附带 |
|---|---|---|
| working | 打字/敲键盘循环 | 偶尔冒汗珠 |
| waiting | 举牌/招手循环 | 气泡「等你确认」+ 轻提示音（可静音） |
| done | 跳跃 + 星星（单次） | 气泡随机一句完成台词 |
| error | 冒汗/瘫坐（单次后转 idle 表情） | 气泡「好像出错了」 |
| idle | 发呆/看书循环 | 5 分钟无事件 → 睡眠动作 |
| offline | 趴下休息 | 控制页对应来源置灰 |

- 台词库：每状态 8–12 条预置短句，本地随机，不接 LLM（MVP）。语气：可爱、简短、不用网络烂梗。
- 多显示器/缩放：跟随 Windows 显示缩放；macOS 需处理刘海屏与多桌面 Space（置顶层级用 panel 级别）。

## 6. 角色包规范（原创生态的根基）

- 角色包 = 一个文件夹：`manifest.json` + `frames/<state>/<动作名>/frame_000.webp...`。
- manifest 字段：`id`、`name`、`author`、`version`、`license`、`anchor`（脚底锚点比例）、`scale`、`states`（每状态对应动作列表、fps、是否循环）、`lines`（可选，角色专属台词覆盖）。
- App 内置 2 只原创角色（一期 1 只即可上线，见第 11 节）；控制页支持导入本地角色包文件夹并校验 manifest，校验失败给出具体缺项。
- 素材制作管线（沿用负责人已验证的流程经验）：AI 生成/手绘帧图 → 透明底处理 → 按状态命名打包 → 在**透明底与深浅两种桌面背景**上验收（不许只在白底看）。

## 7. 控制页规格

- **连接页**：每个来源一张卡片——是否检测到该工具、适配器开关、当前状态、最近事件时间、「测试一下」按钮（发一条模拟事件验证全链路）。
- **宠物页**：角色切换/导入、大小滑杆、不透明度、提示音开关、安静时段（默认 22:30–07:00 不发声、不弹通知，状态照常显示）。
- **通知页**：系统通知开关（按状态勾选）、外发 Webhook 配置（URL + 自定义头，默认关）、测试发送。
- **诊断页**：最近 100 条事件日志、Hub 端口/令牌（令牌只显示前后 4 位）、一键清空日志、导出诊断包（不含令牌全文）。

## 8. 配置管理器（安装体验，成败关键）

- 首次启动向导：检测 `~/.claude`、`~/.codex`、`~/.cursor` 是否存在 → 逐个工具征得用户同意后写入 hook 配置。
- 写入规则（三家通用）：**先备份**（原文件复制到 App 数据目录 `backups/<工具>/<时间戳>/`）→ 解析原配置 → 只合并本产品条目（带固定标识注释/键名 `petlink`）→ 写回并做语法校验（JSON/TOML 解析通过才算成功，失败自动回滚并提示）。
- 幂等：重复启用不产生重复条目；升级 App 后能识别旧条目并原地更新路径。
- 停用/卸载：按备份或按标识精确摘除本产品条目，**其他工具和用户原有 hooks 一律不许动**；卸载 App 时询问是否还原全部配置。
- 每个工具的写入结果要在向导里逐项打勾展示，失败项给出人话原因与手动配置指引链接（本地文档页）。

## 9. 通知规格

- 系统通知：仅在 `waiting` 与 `done`、`error` 状态跃迁时触发，同会话 60 秒内不重复；点击通知尝试聚焦对应工具窗口（尽力而为，失败无妨）。
- 外发 Webhook（Pro 功能雏形，一期先做基础版）：状态跃迁时 POST 一份与 3.2 同构的 JSON 到用户配置的 URL；失败重试 1 次后放弃并记日志。此通道用于对接负责人已有的中转/短信体系（xiaoran.onoe.cn 协议兼容：外发体允许附带 `kind` 字段映射 done/confirm/remind）。
- 短信不内置（一期不碰电信合规），只经 Webhook 由用户自有中转处理。

## 10. 技术选型

- 桌面框架：**Electron**（团队已有经验、跨 Win/Mac 同一套代码）；主进程 Node ESM；渲染层原生 Web 技术或轻量框架（执行方选一并在交付说明中注明，不要引入重型全家桶）。
- 适配器脚本：Node 单文件、零依赖、CommonJS/ESM 均可，要求冷启动快、无常驻。
- 工程结构建议：`apps/desktop`（Electron）、`packages/protocol`（状态协议与校验）、`packages/adapters`（三家脚本 + 通用 CLI）、`packages/config-manager`（配置合并/备份/回滚，独立可测）、`characters/`（内置角色包）、`docs/`。
- 目标系统：Windows 10/11 x64、macOS 12+（Intel/Apple Silicon 通用包）。
- 打包：electron-builder；一期不签名（安装页写明系统拦截时的放行步骤），二期视收入情况购证书/走 Apple 公证。
- 自动更新：二期再做，一期提供手动检查更新（读 GitHub Release 或自有静态 json）。

## 12. 验收标准（Muse 按此逐项验，不过不算交付）

1. **链路延迟**：在本机触发 Claude Code 的 Stop 事件，桌宠 1 秒内切到 done 动作；waiting 同理。
2. **配置安全**：用带既有 hooks 的 fixture 配置跑启用→停用全流程，最终文件与原始文件**逐字节一致**（除本产品条目存续期间）；解析失败的坏配置不写入且能回滚。
3. **不阻塞宿主**：Hub 未启动时跑 Claude Code/Codex 全流程，无报错、无可感延迟。
4. **五态截图**：桌宠五种状态各一张实机运行截图（深色与浅色桌面背景各一组），交付时随附——纸面检查不算验收。
5. **多会话聚合**：同时跑两个 Claude Code 会话，一 waiting 一 working，桌宠显示 waiting，控制页两条明细无误。
6. **双机实测**：Windows 真机 + Mac 真机各完成一次「装向导→干活→等确认→完成」全流程（负责人侧配合）。
7. **洁净自查**：仓库全量搜索不得出现 AI Buddy 的代码片段、角色名、素材文件名与文案句子；执行方在交付说明中签注已自查。

## M6 P2 本机扩展（2026-11-11）

`typing` 是计数专用 source，沿用 `hub.json` 端口发现、`token` 文件和 `X-PetLink-Token`，POST `/v1/event`。示例：

```json
{"v":1,"source":"typing","session":"typing-helper","state":"working","count":12,"ts":1794355200000}
```

`count` 必须为 0–1,000,000 的整数；只允许 working/idle，不允许 title/project/beat。每 5 秒发送一段计数，零计数也用于连接心跳。10 秒内有正计数且真实会话聚合为 idle 时才跟随 working；15 秒未收到上报显示未连接。Hub 按本机日期累计，`typing-counts.json` 只保存日期与当日总数，重启不恢复连接状态。助手不持久化任何输入数据；Hub 不可用时该段计数丢弃，下个周期重试连接。

聊天通过主进程转发到用户配置的 OpenAI 兼容端点（完整 `/chat/completions` URL）。最近 20 轮历史（最多 40 条）加当前消息与人设，30 秒超时，禁止跟随重定向。本机 `desktop.json` 保存 API Key，renderer 快照只得到 `***`；聊天历史在同目录 `chat-history.json`，最近 100 条，可清空。消息会发送到所配置服务；这不是肖大大本人的记忆或会话。
